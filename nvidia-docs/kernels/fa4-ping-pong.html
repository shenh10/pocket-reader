00读一个尚未合并的优化

两个 S/P 槽让下一块 QK 提前进入计算；同一份 O 累加器保留了 PV 与 rescale 的顺序依赖。看懂这两件事，才能理解为什么“双缓冲”既有收益，也有边界。

01先把数学依赖写完整

按实际遍历顺序给 KV tile 编号 i。令 Sᵢ=QKᵢᵀ/√d，维护行最大值 m、分母 l 与未归一化的输出 O。这里用自然指数表达，源码可等价使用 exp2 与缩放。

mᵢ = max(mᵢ₋₁, max(Sᵢ)) αᵢ = exp(mᵢ₋₁ − mᵢ) Pᵢ = exp(Sᵢ − mᵢ) lᵢ = αᵢ lᵢ₋₁ + sum(Pᵢ) Oᵢ = αᵢ Oᵢ₋₁ + PᵢVᵢ 最终输出 = O / l

QKᵢ₊₁ 不依赖 Pᵢ 或 Oᵢ。可是计算 αᵢ₊₁ 需要新最大值；重缩放 Oᵢ 需要等 PVᵢ 写完；PVᵢ₊₁ 又必须在 O 重缩放后累加。可提前的是新 score 的生成，并非整条输出递推。

可推进：QK → S/PQKᵢ₊₁ 写另一个槽，与 softmaxᵢ 有机会重叠。
必须顺序：O 的更新PVᵢ 完成 → 乘 αᵢ₊₁ → PVᵢ₊₁ 累加。
数值自测：新块提高最大值，为什么不能直接把 PᵢVᵢ 加进旧 O？

旧 O 使用旧最大值作为指数基准；新块使用新基准。若旧 m=2、新 m=4，旧 O 必须先乘 exp(-2)。省掉 rescale 会把两种标度相加，最终除 l 也不能修复。

02S/P 增加槽位，O 没有增加副本

启用时 q_stage 仍等于 1，s_p_o_stage 变成 2。stage 0/1 的 score/概率位于不同 TMEM 列；PV 的目标却是 tmem_o_offset[stage % q_stage]，两种 stage 都落到同一个 O。

03一次迭代里，谁等谁

步骤MMA / loadsoftmax / correction 与依赖
填充流水线加载 K₀，发 QK₀ 写 slot 0；随后加载 K₁。softmax 读 S₀，生成 P₀；首块没有旧 O 要 rescale。
重叠窗口发 QK₁ 写 slot 1，然后拿到 V₀。softmax₀ 与 QK₁ 可重叠；PV₀ 等 P₀ 就绪。
推进PV₀ 完成后为 O 发布完成信号；后续 QK₂ 复用 slot 0。处理 S₁ 得到 α₁；若需 rescale，等 O₀ 完成，再缩放同一 O。
下一次累加PV₁ 只有在 P₁ 可用且 O rescale 完成后才能发起。P 的发布与 correction 的完成合起来满足握手，slot index 和 phase 都要正确。
排空最后一个 QK 已先发出；收尾执行最后 PV，发布 O 完成。最终归一化/epilogue 仍需等数据完整，不能省略尾部协议。

04slot 和 phase，是两个不同的计数

该 PR 用持续递增的计数表示 stage 使用次数。它在工作 tile 循环之外初始化；跨 tile 不能凭直觉全部清零。slot 交替选择存储位置，phase 区分同一 barrier 的下一轮使用。

slot(c) = c & 1 phase(c) = (c >> 1) & 1 c = 0,1,2,3,4,5 slot = 0,1,0,1,0,1 phase = 0,0,1,1,0,0

05门槛是性能策略，不是硬件能力表

此 PR 的条件还包括 arch∈{100,110}、q_stage=1、head_dim_v=head_dim、tile=128×128、非 2-CTA，以及无 score/mask mod、block sparsity、learnable sink。arch 是这份实现的内部数字条件，不据此推导未验证产品支持；不能把“Blackwell”品牌直接当作通过检查。

paged KV 要 page_size=128；连续 KV 也可通过。num_splits=1 不受每 split block 阈值限制；多 split 时 head_dim=64 需要至少 16 个 block，head_dim=128 需要至少 64 个 block。局部注意力先估计实际加载长度，以下实验固定非 local。

为什么 KV=8192、d=128、splits=2 会不启用？

8192/128=64 个 block，分成两份约 32 个，小于 d=128 的 64-block 门槛。同样长度设 splits=1 可通过这项判断。阈值体现作者在特定实现上的取舍，不能概括为“双缓冲在短序列绝不有效”。

06把优化变成可证伪的实验

作者报告 B200 上部分 decode 配置的有效带宽最多提升约 16%。在同工作量下，带宽 ×1.16 对应延迟 ÷1.16，约下降 13.8%，并非延迟下降 16%，更不是完整服务加速 16%。

验证问题A/B 方法可否定结论的现象
收益是否来自这项改动？同一个固定 head，在全新进程中分别开启/关闭 FA_DISABLE_S_PING_PONG；保持 dtype、split、layout、输入与时钟条件一致。两次选中的 tile/backend 不同，或 gate 根本没开：不能归因给 ping-pong。
QK 与 softmax 是否重叠？用 kernel 内 trace/IKET 核对各 warp 的 QK、softmax、correction 区间；普通系统时间线不足以证明 warp 内重叠。QK 仍等待 S/P 释放，或 overlap 被 load 延迟完全覆盖。
数值是否正确？比较 O 和 LSE；覆盖页尾、局部窗口、不同 split、空/短尾块和多 tile；再对 FP32 reference 验证。A/B 一致却共同偏离 reference，不能证明数学正确。
是否值得用于服务？单 kernel、attention 层与完整 decode step 分别测；记录 P50/P95，交错运行对照。kernel 改善被图外开销或其他层抵消；服务 ITL 无显著变化。

旧版 FA4 主干案例、本文的未合并优化、下一步 FlashMLA 的实现，应保持各自版本与独立证据。不要把“博客解释过”替代“本地已验证这条路径”。
