01 · 第一优先 · 测量与后端选择

FlashInfer Autotuner v2: Tune the Way You Serve

Yang Xu 等 / FlashInfer · 2026-09-22 · 项目原作者博客

文章观点：作者把 tactic 的选择目标分成完整 eager 调用与 CUDA Graph replay：候选实现的 host 开销不同，单看 device time 会排错名次。缓存还要记录运行环境、操作形状、layout/量化等配置和计时策略。

我的提炼：任何“最快 kernel”结论都必须先写清调用边界；缓存命中也需要有效性条件。

适用边界

这是作者对 v2 的设计和实验报告，旧 FlashInfer 2025-11-19 快照不能证明 v2 行为；2026-11-20 已在专题 05 单独核对 v2 合并版本的测量与缓存路径。

拟做：同一 shape 分别测 device、eager 和 Graph replay，报告 tactic 排名、相对最优候选的 regret、首次编译/调优与热缓存成本；再追踪 vLLM/SGLang 实际采用的 backend。

02 · Attention · 流水线与缓冲区生命周期

Optimization diaries: S/P ping-pong for FlashAttention-4 decode

Colfax Research · 2026-09-07 · 实现者技术博客

文章观点：文章利用 decode 路径闲置的第二个 TMEM 槽，让下一块 QK 与当前 softmax 重叠。实现同时改变 K/V 加载顺序，并分别跟踪槽位和 barrier phase；PV 仍须等待 P 可用和 O accumulator 释放。

我的提炼：读双缓冲时，要分别画数学依赖和存储复用依赖；“没有数学依赖”并不等于可以无同步覆盖缓冲区。

适用边界

作者报告 B200 上部分 head_dim=64/128、GQA 16:1/16:2 decode 配置的带宽提升最高约 16%；不是所有 shape 的收益，也不是服务端到端加速。

拟做：固定 PR 前后 commit，扫 KV 长度、query 长度与 GQA；先测正确性和延迟，再用 IKET 检查 QK/softmax 是否重叠、PV 是否仍阻塞在 O 上。

03 · MoE · 训练激活内存与 IO

SonicMoE: A Hardware-Efficient and Software-Extensible Blueprint for Fine-Grained MoEs

Tri Dao 博客 / SonicMoE 团队 · 精确发布日期未核实 · 2026 年路径 · 项目原作者博客

文章观点：细粒度专家会放大按 top-k 展开的中间张量。作者通过运行时 gather、融合激活，并重排 routing-weight 梯度的收缩顺序，避免为 backward 缓存大块专家输出；无需为此重算该 GEMM。

我的提炼：先检查哪些中间结果有必要物化，再优化 GEMM；“少保存一个大张量”可能比提高局部 TFLOPS 更有价值。

适用边界

文中内存随粒度不变的比较固定 T、d 和 n×top-k；实验聚焦单 GPU、EP=1 的 MoE 层训练，不能直接推导多机推理收益。页面未核实到精确发布日期。

拟做：推导并数值核对 routing-weight 梯度等价式，按张量列出生命周期和读写字节，再比较 varlen-M/varlen-K grouped GEMM；同时报告 forward、backward 和峰值内存。

04 · MoE · 通信计算融合与低精度

MegaMoE in FlashInfer: Fused Expert-Parallel MoE Kernels

Anerudhan Gopal 等 / FlashInfer · 2026-09-22 · 项目原作者博客

文章观点：作者用 persistent kernel 融合 dispatch、量化、两次 grouped GEMM 和 combine，并借对称内存重叠通信计算。文中小 token/rank 场景并不总由新后端胜出；combine 的通信精度也是性能变量。

我的提炼：比较融合收益，要把 launch、HBM 往返、通信重叠和量化分别做消融；选择阈值应随 workload 而定。

适用边界

端到端对比中的 native/fi_dg 用 MX checkpoint，fi_cutedsl 用 NVFP4 转换权重，不能当作同精度融合实验。作者的 200 题 GSM8K 检查也不能证明跨任务精度等价。

拟做：优先建立同精度、同模型与拓扑的 split/fused 对照，扫 tokens/rank、路由偏斜和通信 dtype；分别报告 MoE 层耗时、TTFT、ITL 和模型质量。

06 · Attention · 页表到加载布局

FlashInfer 0.2 - Efficient and Customizable Kernels for LLM Inference Serving

FlashInfer Community · 2024-12-16 · 项目原作者博客

文章观点：文章把 paged attention 放进 block/vector-sparse 的统一视角：通过加载端的 layout/stride 表达间接寻址，复用 attention 计算模板；也交代了 JIT 特化与可变长度 CUDA Graph 支持。
