# KDA RecoverSSM runner integration evidence

Fixed source: `vllm-project/vllm@24c72a76b96bf8d73190a4bb66d47dc8c3eb2134` (PR #63045 head confirmed by API at collection). Read-only source tracing; **no tests, GPU execution, model loading, or numerical validation performed**. `integration/receipts.json` records SHA-256, official immutable links and new API Git blob IDs; reused sources were hash-checked. `pr-63045.json` is a mutable PR-body snapshot, not evidence that its claimed test results were independently reproduced.

## Bounded conclusion

The standard V2, single-batch, PP=1 path has a complete static callback chain from metadata recording through sampler output to the layer commit context. Non-prefix/non-align mode still commits: its `None` return means there is no align bookkeeping, **not** that state commit was skipped. The legacy V1 runner has no RecoverSSM import/callback/name in its fixed-source file, consistent with the PR body's missing-commit warning. The fixed config nevertheless only requires V2 for **align** mode and contains no RecoverSSM-specific DBO rejection in that validation block. Do not present the PR-body promise of universal V2/DBO guards as implemented at this SHA.

## Exact call chain

1. V2 selects `MambaHybridModelState` for hybrid/attention-free models unless the model overrides the selection ([selection](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/v1/worker/gpu/model_states/__init__.py#L29)); its constructor creates `RecoverSSMState` whenever `use_kda_recoverssm` is true, independent of align ([construction](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/v1/worker/gpu/model_states/mamba_hybrid.py#L89)). This is conditional source tracing, not a runtime proof of a full Kimi-K3 deployment's class selection.
2. `prepare_attn` builds attention metadata and calls `record_step` ([record callback](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/v1/worker/gpu/model_states/mamba_hybrid.py#L325)); `record_step` collects RecoverSSM metadata once per attention group, clears the pending step during capture ([record_step](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/v1/worker/gpu/model_states/recoverssm.py#L19)). KDA metadata constructs commit metadata only for speculative decode rows and carries the shared context ([commit metadata](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/models/kimi_k3/nvidia/kda_metadata.py#L666), [context attachment](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/models/kimi_k3/nvidia/kda_metadata.py#L728)).
3. `sample_tokens` calls `sample`, which dispatches to normal or rejection sampler and returns `sampler_output.num_sampled` ([sampler dispatch](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/v1/worker/gpu/model_runner.py#L1661), [return count](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/v1/worker/gpu/model_runner.py#L1702), [sample call](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/v1/worker/gpu/model_runner.py#L2175)). Normal sampling starts with one token/request, then zeroes unfinished chunked prefill; rejection sampling obtains its verified count then applies the same count postprocessor ([normal count](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/v1/worker/gpu/sample/sampler.py#L190), [rejection count](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/v1/worker/gpu/spec_decode/rejection_sampler.py#L449), [prefill/count adjustment](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/v1/worker/gpu/input_batch.py#L513)). Rejection sampler resampling increments the accepted draft count by one ([resampled/bonus increment](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/v1/worker/gpu/spec_decode/rejection_sampler_utils.py#L1024)). Thus this is the sampled output count used as the committed input-prefix length; it must not be described as merely the number of accepted draft tokens.
4. After sampling, `postprocess_sampled` runs `post_update` then `model_state.postprocess_state(idx_mapping, num_sampled, computed_tokens)` ([postprocess call](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/v1/worker/gpu/model_runner.py#L2261), [postprocess implementation](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/v1/worker/gpu/model_runner.py#L1705)). The hybrid callback scatters the count, then passes the original tensor to `commit_step` ([hybrid callback](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/v1/worker/gpu/model_states/mamba_hybrid.py#L350)).
5. `commit_step` consumes and clears `_step`, skips integer counts or missing steps, and calls each metadata's `commit_recoverssm_state(num_sampled)` ([commit_step](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/v1/worker/gpu/model_states/recoverssm.py#L38)). KDA metadata calls `context.commit` before checking whether align exists ([KDA commit callback](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/models/kimi_k3/nvidia/kda_metadata.py#L271)). Mixed-batch request indices map speculative rows back to the sampler count tensor.
6. The context validates its inputs, prepares the plan, compacts convolution history and runs the selected CuTe or Triton KDA fold across layers ([context commit](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/models/kimi_k3/nvidia/ops/recoverssm.py#L889), [plan](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/models/kimi_k3/nvidia/ops/recoverssm.py#L947), [conv and backend dispatch](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/models/kimi_k3/nvidia/ops/recoverssm.py#L971)). The plan clamps length to `[0, query_len]` and `SPEC_QUERY_LEN` ([commit-length formula](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/models/kimi_k3/nvidia/ops/recoverssm.py#L258)); optional request mapping selects the correct count. Context creation is lazy in the metadata builder ([context construction](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/models/kimi_k3/nvidia/kda_metadata.py#L339)).

## Modes and evidence matrix

| Path/property | Implementation present | Static call chain verified | Integration status / limit |
|---|---|---|---|
| V2 ordinary single-batch speculative decode | Yes | record → sample → postprocess → commit metadata → context | Untested; conditional on hybrid state and RecoverSSM metadata selection |
| V2 non-align / no prefix cache | Yes | Same context call; `align=None` returns only after commit | Untested; no align running-column/reset kernel |
| V2 align prefix caching | Yes | Same commit plus block-table/computed-count args; returned metadata triggers running-column update and neutral acceptance reset | Untested; no end-to-end cache-hit/migration/preemption proof |
| FULL graph capture | Yes | `for_capture=True` clears `_step`; capture itself does not retain a pending commit | Untested capture/runtime behavior |
| FULL graph replay | Yes | Real run calls `prepare_attn` with `for_capture=False`, stages request buffers, then replays model; sampling/postprocess occurs afterward | Static standard single-batch path only; no replay numerical test |
| Legacy V1 non-prefix | Layer/metadata implementation exists | No RecoverSSM callback/import/name in `gpu_model_runner.py`; V2 helper is not integrated there | Missing callback supported by inspected runner, not an executed reproduction |
| DBO / multiple microbatches | Generic runner branch exists | **Not traced to safe per-microbatch record ownership/commit** | Unresolved; shared record/context lifetime requires separate analysis; no support claim |

FULL graph distinction: [microbatch versus ordinary metadata branch](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/v1/worker/gpu/model_runner.py#L1917), [ordinary prepare_attn and capture flag](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/v1/worker/gpu/model_runner.py#L1940), [FULL replay](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/v1/worker/gpu/model_runner.py#L2032). Metadata stages speculative state/query/acceptance buffers for eligible full-graph batches ([staging](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/models/kimi_k3/nvidia/kda_metadata.py#L625)). Commit is a Python post-sampling callback; graph capture of verify does not imply capture of sampling or commit. Align bookkeeping is [post-commit align update](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/v1/worker/gpu/model_states/recoverssm.py#L52) and [remaining align postprocess](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/v1/worker/gpu/model_states/mamba_hybrid.py#L387). These observations do not establish replay correctness or stream synchronization experimentally.

## Support boundaries and missing evidence

Fixed config ([RecoverSSM validation](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/config/vllm.py#L3482)) rejects stochastic rounding, PP>1 and non-Triton Mamba backend; the V2 check is conditional on align. This Triton Mamba backend requirement does not mean the inner RecoverSSM verify/fold cannot choose CuTe. CuTe eligibility is separately checked ([CuTe eligibility](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/models/kimi_k3/nvidia/recoverssm/kernels.py#L37)): SM10x family, head dim 128, required convolution shape/no bias, bounded window, BF16 activations/conv state/SSM state, BF16 or FP32 conv weights and compatible gate. Runtime fallback remains relevant for unsuitable tensor alignment ([verify fallback](https://github.com/vllm-project/vllm/blob/24c72a76b96bf8d73190a4bb66d47dc8c3eb2134/vllm/models/kimi_k3/nvidia/kda.py#L1021)). No claim is made for arbitrary GPU, dtype, shape, variant or model.

Missing for stronger claims: actual deployment/model-state selection receipt; GPU-enabled full-run integration trace; graph replay and multi-step numerical results; microbatch (`ubatch_runner`) ownership/callback trace; exhaustive whole-tree V1 call-site audit; stream/lifetime correctness under scheduling and cache rebinding. PP code paths exist but PP>1 is explicitly rejected for RecoverSSM and are not support evidence. No numerical results from the PR body are promoted to locally verified results.
