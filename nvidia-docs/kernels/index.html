02框架名不是 kernel 名

新增完整分支追踪与计时实验 →

先确认运行时选择，再进入案例。这里列的是指定快照中可核对的分支；安装版本、GPU、dtype、模型形状和配置都可能改变结果。

入口已核对的事实阅读时的边界
vLLM FlashInfer backend非 cascade decode 还可能直接调用 TRT-LLM；下述限定 FIDecode wrapper 分支：构造时传入 use_tensor_cores=True；NVFP4 选择 trtllm-gen，否则 auto。不能从“vLLM 用 FlashInfer”推断它执行案例 01 的 SIMT kernel。
SGLang FlashInfer backendshould_use_tensor_core 接收 KV dtype、Q/KV head 数；wrapper 使用 decode_backend 与该决策结果。dtype 可能先被 workspace 转换。核对真实传入类型及 GQA 比率。
FlashInfer decode wrapperplan/run 对 trtllm-gen、Tensor Core、普通 decode 分别处理。案例 01 只深入普通 SIMT 路径；案例 02 来自独立的 FlashAttention 实现。
SGLang MoE runnerTriton 路径与 FlashInfer CUTLASS / TRT-LLM 等 runner 并存。案例 03 的索引推导限定 aligned Triton 路径；grouped GEMM 是对照实现。
DeepEPEPv2 使用 ElasticBuffer；仓库仍保留 legacy Buffer。案例 04 不把 V1 的 NVSHMEM 协议、低延迟接口套到 EPv2。

03达到工程深度，要留下哪些证据

层次本站提供还需要实机完成
正确性明确形状、索引、边界；CPU 验证 split merge 与 MoE grouped/scatter 结果。GPU dtype 误差、sanitizer、不同尾块与版本回归。
资源从指定源码算 SMEM、TMEM、padding、有效流量。编译后寄存器、spill、occupancy、实测缓存命中。
性能每篇给出可证伪的假设和对照实验矩阵。固定硬件/软件、预热、CUDA event、Nsight 时间线和端到端延迟。

源码时间跨度为 2025–2026：FlashInfer 使用 2025-11-19 的上游基线，其余仓库也分别固定 commit。它们适合解释实现，不能当作 2026 年 11 月各项目最新行为的总览。

FlashMLA、FlashInfer SM100 MLA、SonicMoE 等尚未展开为独立案例；它们是后续扩展方向，不计入当前深读覆盖。
